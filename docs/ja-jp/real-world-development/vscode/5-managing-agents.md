GitHub Copilot を agent mode で使うと、コードベースの探索、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、フォローアッププロンプトで作業を調整しながら、エディターを離れずに進められます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中で指示を追加し、ハイコントラストモードに加えてライトモードも実装します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替えも追加してほしいとのことです。新しい会話を最初から始めるのではなく、既存のセッションに追加の指示を出します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各ステップが表示されます。各ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を取り消し、エージェントにやり直してもらうには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可を求められると、エージェントは一時停止して **Allow** を表示します。許可するコマンドは内容を確認してから選択してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。完了すると、変更の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えも依頼します。会話を続けることで、エージェントは前の作業で変更したコンポーネント、スタイルの方針、local storage を使った設定方法などのコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモードの追加を提案します。
3. 新しい編集が提案されるたびに、差分を確認し、**Keep** または **Undo** を選択します。
4. エージェントの方針が意図と異なる場合 (たとえば、好ましくない方法で切り替え UI を再構成しようとする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な追加指示を送信できます。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すよりも効率的です。フォローアッププロンプトで調整を依頼できます (例: 「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」)。方針を修正したり (例: 「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合してください」)、範囲を広げたり (例: 「両方の切り替えにキーボードショートカットも追加してください」) できます。

## 作業内容をレビューする

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して案内しました。ファイル編集を確認しながら承認または取り消し、コンテキストを保ったままフォローアッププロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- セッションの途中で追加の指示を送りました。

[次のレッスン][next-lesson]では、アクセシビリティに関する変更をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが行った変更をレビューします。
